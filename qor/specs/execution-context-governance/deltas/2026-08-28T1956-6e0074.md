# Phase 240 Execution-Context Governance Delta

## ADDED Requirements

### Requirement: Model identity is provenance only
Governance admission MUST treat declared or responder model identity as provenance rather than execution authority.

#### Scenario: Unknown model family
- GIVEN a governed skill invocation with an unknown or non-vendor-specific model family
- WHEN execution-context admission is evaluated
- THEN model identity alone does not deny entry

### Requirement: Hard capability absence requires complete inventory
A hard execution capability MUST be classified as missing only when the runtime declares its capability inventory complete and the requirement is absent.

#### Scenario: Incomplete telemetry
- GIVEN a runtime whose capability inventory is not declared complete
- WHEN a required capability is not observed
- THEN the requirement is reported as unverified rather than missing

### Requirement: Rendering adaptation is bounded
Runtime rendering adaptation MUST select only a recipe explicitly admitted by the governed skill contract.

#### Scenario: Unadmitted rendering hint
- GIVEN a rendering hint outside the skill's admitted recipe set
- WHEN the execution context selects a rendering recipe
- THEN selection falls back deterministically without changing governance semantics

### Requirement: Active skills do not pin named models
Executable skill admission metadata MUST remain free of named-model allowlists and vendor capability tiers.

#### Scenario: Corpus regression
- GIVEN the active qor/skills corpus
- WHEN admission metadata is inspected
- THEN retired model_compatibility and min_model_capability fields are absent

### Requirement: Audit entry is vendor-neutral
The audit runtime MUST block entry only when a declared hard execution requirement is proven missing under complete capability telemetry.

#### Scenario: Non-vendor-specific audit host
- GIVEN a non-vendor-specific model identity with no proven missing hard requirement
- WHEN qor-audit checks execution context
- THEN the audit protocol remains reachable

### Requirement: Fabrication protection is independent
The NR-001 and NR-002 fabrication-risk protections MUST remain binding independently of model identity or rendering recipe.

#### Scenario: Compatibility transition
- GIVEN the retired model-pinning authority mechanism has been removed
- WHEN compatibility linting or compiled variants are evaluated
- THEN fabrication-risk protections remain active
