# Plan: publication-boundary sweep and enforcement (Phase 208)

**change_class**: feature

**doc_tier**: standard

**terms_introduced**: none

**boundaries**:
- limitations: The exemption marker is per-line and requires a written reason.
  It grants nothing on its own; it only lets a file record an exception the
  doctrine already allows. There is no wildcard, no per-file exemption, and no
  directory-level suppression.
- non_goals: No rewriting of the `qor/vendor/` third-party tree, which is
  already a documented carve-out. No change to the four structural detectors or
  to the gitignored operator terms overlay. No renaming of skills or files.
- exclusions: Untracked and gitignored surfaces are out of scope; the doctrine
  governs what this repository publishes.

## Open Questions

None.

## Locked Decisions

**LD-1 — The lint cannot express the exceptions its own doctrine grants, which
is why it has been permanently red and therefore un-actionable.**

`qor-logic scripts publication_boundary_lint --repo-root . -> 85 tracked non-vendor findings across 42 files`

Classified by remediation class, 27 of those 85 findings are the
`license: Proprietary (<owner>)` line. Phase 172 explicitly preserved
exactly that text: its seal records "Exceptions preserved: two
`license: Proprietary` skill lines + `qor/vendor/` third-party attribution
(legally required text)." The grant exists in doctrine and has no expression in
the tool, so every run since Phase 172 has reported granted exceptions as
violations. A fail-closed control that cannot be satisfied is a control that
gets ignored, which is why the lint is wired to no gate.

`grep -rn "publication_boundary_lint" .github/workflows/ qor/skills/governance/qor-substantiate/SKILL.md qor/compliance/control_matrix.json -> no matches`

**LD-2 — The repository already has an inline exemption idiom to mirror.**

`grep -n "prose-lint" qor/scripts/prose_test_lint.py -> 14: Allowlist: an assertion carrying a trailing ``# prose-lint: ok=<reason>`` comment | 30: _ALLOW_RE = re.compile(r"#\s*prose-lint:\s*ok=(\S.*?)\s*$")`

`prose_test_lint` distinguishes unexplained findings from exempted-with-reason
ones and fails only on the former. The boundary lint adopts the same shape, with
the comment-character prefix dropped so one marker works in Markdown, Python,
and YAML alike.

**LD-3 — Findings divide into six remediation classes, and only two require
judgment.**

Measured over the tracked non-vendor surface:

| Findings | Files | Class | Remediation |
|---|---|---|---|
| 27 | 27 | Declared license exception | Exemption marker |
| 18 | 12 | Generated under `qor/dist/` | Regenerates from source |
| 15 | 3 | Stale tracked skill install copies | Untrack |
| 9 | 3 | Historical plan files | Anonymize; one exemption |
| 8 | 4 | Live docs and skill sources | Anonymize |
| 6 | 3 | Phase 205 gate artifacts | Sweep, regenerate sidecars |
| 2 | 2 | Frozen archive | Exemption marker |

The `.claude/skills/` copies are installed artifacts, not source: four files
tracked by an old commit, carrying both identity terms and a stale
`qor-logic-plus` CLI name that disagrees with this repository's `qor-logic`.
They are regenerated by `qor-logic install` and belong to the operator, so they
are untracked rather than edited.

## Phase 1: Give the lint an exemption idiom

### Unit Tests

- `tests/test_publication_boundary_lint.py::test_line_with_exemption_marker_is_not_reported` -
  scans text where an identity term and a foreign URL each sit on a line
  carrying `boundary-lint: ok=<reason>` and asserts `scan_text` returns no
  findings for those lines, while an unmarked line beside them still reports.
- `::test_exemption_marker_requires_a_reason` - asserts a bare
  `boundary-lint: ok=` with no reason text does NOT suppress the finding, so an
  empty marker cannot silence the control.
- `::test_exemption_is_per_line_not_per_file` - a marked line and an unmarked
  line in the same document; asserts exactly one finding is returned and it
  names the unmarked line number.

### Affected Files

- `qor/scripts/publication_boundary_lint.py` - `_ALLOW_RE` plus a per-line
  guard in `scan_text`.

### Changes

A line matching `boundary-lint:\s*ok=(\S.*?)\s*$` yields no findings. The
reason is required by the `\S` anchor, matching `prose_test_lint`. The marker is
comment-syntax agnostic so Markdown, Python, and YAML all express it.

## Phase 4: Make the clean state enforceable

### Unit Tests

## Definition of Done

### Deliverable: expressible exceptions

- **D1**: An exception the doctrine grants can be recorded where it applies,
  with a written reason, and the control stays fail-closed everywhere else.
- **D2**: `publication_boundary_lint._ALLOW_RE` plus a per-line guard in
  `scan_text`.
- **D3**: Seal entry records that 27 of 85 findings were doctrine-granted
  exceptions the tool could not express, and that this is why the lint was
  wired to no gate.
- **D4**: Three tests assert `scan_text` return values: marker suppresses,
  reasonless marker does not suppress, and suppression is per-line.

### Deliverable: a boundary-clean tracked surface

- **D1**: No tracked file outside the `qor/vendor/` carve-out names a repository,
  product, or identity outside Qor-logic without a recorded reason.
- **D2**: 85 findings resolved across the six classes in LD-3.
- **D3**: Seal entry reports the per-class counts and names the two docs that
  were anonymized by operator decision rather than mechanically.
- **D4**: `qor-logic scripts publication_boundary_lint --repo-root .` exits 0.

### Deliverable: enforcement

- **D1**: A future change that reintroduces an outside identity fails before
  merge rather than accumulating silently.
- **D2**: CI runs the lint in the `gate-chain-completeness` job.
- **D3**: Seal entry records the wiring and the doctrine update.
- **D4**: `test_live_tracked_surface_is_boundary_clean` fails if any tracked
  file regresses, which is verifiable by reverting one anonymization.
