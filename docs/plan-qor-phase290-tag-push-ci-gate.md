## Problem

GH #482: Step 9.5.5 tags the seal commit by its exact SHA (`references/
release-and-tag-timing.md` -- deliberate, closes the Phase 33 off-by-one bug).
Step 9.7 pushes that tag once `git merge-base --is-ancestor "$SEAL_COMMIT"
origin/main` succeeds. GitHub only runs the `CI` workflow on pushed branch
heads, not on every ancestor. A commit stacked on the phase branch after the
seal (before push/merge) moves the branch head past the seal commit; the
ancestor check still passes once merged, but no CI run for the seal commit's
own SHA exists or ever will. `release.yml`'s `release_ci_gate` (Phase 163)
then correctly refuses the publish -- in a separate workflow run nobody has
reason to open, days after the seal succeeded and the PR merged. Observed on
`v0.172.1`:

> `REFUSE: no CI run found for 3b7b0aac... (refusing release)`

Each control is individually correct; the interaction is invisible by
construction, per the issue's own "Scope note".

### Changes

`tag_ci_gate.py`:

- `evaluate(ancestor_ok: bool, runs: object, head_sha: str) -> GateResult` --
  pure. `ancestor_ok=False` -> not ready, "seal commit not yet on origin/main;
  tag held local" (unchanged Step 9.7 behavior for the ordinary pre-merge
  case). `ancestor_ok=True` -> delegate to `release_ci_gate.evaluate(runs,
  head_sha)`; on failure, "seal commit is on origin/main but has no green CI
  run of its own for `<sha>`: `<release_ci_gate message>`; a commit likely
  landed on the branch after the seal -- re-seal or trigger CI for `<sha>`
  before pushing the tag"; on success, ready with the underlying message.
- `main(argv)` -- `--sha <sha>` (required), `--on-main` (store_true,
  default False). When the flag is absent, evaluate immediately with
  `ancestor_ok=False` and skip stdin entirely (no wasted `gh api` call from the
  caller's shell in the ordinary not-yet-merged case). When present, read the
  runs JSON from stdin exactly like `release_ci_gate.main`; print `OK`/`REFUSE`;
  exit 0/1.

Step 9.7 bash block (`SKILL.md`), inserted between the existing ancestor `if`
and the tag push:

```bash
git fetch origin main
if git merge-base --is-ancestor "$SEAL_COMMIT" origin/main; then
  if gh api "/repos/$(gh repo view --json nameWithOwner -q .nameWithOwner)/actions/workflows/ci.yml/runs?head_sha=${SEAL_COMMIT}&per_page=100" \
      | python -m qor.scripts.tag_ci_gate --sha "$SEAL_COMMIT" --on-main; then
    git push origin "$SEAL_TAG"
  else
    echo "Seal commit $SEAL_COMMIT has no green CI run of its own; tag $SEAL_TAG held local. See GH #482."
  fi
else
  echo "Seal commit not on origin/main yet; tag $SEAL_TAG held local. Push after merge: git push origin $SEAL_TAG"
fi
```
